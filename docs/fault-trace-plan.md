# 故障查線功能：設計與實作規格

情境：使用者回報「3F 座位 A-02 不能上網」。IT 要在圖上快速找出這台設備到網路入口的整條路線，逐段檢查並記錄結果，還要知道某個點故障會影響哪些人。

## 一、入口

- 右下角工具列新增「查線」按鈕（扳手圖示）。按下後進入「查線模式」，提示「點選有問題的設備或網路埠」。
- 設備的右鍵選單、屬性列（ctx）、屬性面板也加「從這裡查線」。
- 按 Esc 或再按一次「查線」離開。查線模式下，畫布外框改成琥珀色細框，讓人知道目前在查線。

## 二、查線清單面板（核心）

選定起點後，右側開啟「查線清單」面板，沿用 `#insp` 抽屜的外觀和捲動方式。

- 路線用現有的 `trace()` 加上 `upstream()` 產生，依序列出每一段：
  - 終端網卡（埠）
  - 跳線（線號、線材、長度）
  - 資訊座桌面埠 ⇄ 牆內埠
  - 牆內線（虛線）
  - 配線架後 ⇄ 前埠
  - 跳線
  - Switch 埠（VLAN、PoE、LACP）
  - 上行線
  - 核心 Switch、防火牆、ISP
- 每段一列，提供四種狀態：未檢查（灰）、正常（綠）、可疑（琥珀）、故障（紅）。另有備註欄，可記錄量測結果，例如「測線器 4、5 芯斷」。
- 畫布同步上色：路線上的線、埠、設備依狀態顯示顏色。故障段加紅色閃爍外框，其他不在路線上的元素淡化（沿用 dim）。
- 面板頂端顯示「建議下一步檢查：xxx」。用二分法挑選目前「未檢查」區段的中間點，點一下會自動對焦到那一段。
- 狀態存在 `S.faults`，格式為 `{id, start, created, items:{key:{st,note,at}}, closed}`。key 是 `port:<id>`、`cable:<id>` 或 `dev:<id>`。這樣匯出 JSON 和分享連結都會帶著狀態。`normalize()` 要補上預設值。

## 三、自動健檢（找出可疑點）

路線產生後，自動對每一段跑規則，命中的段落先標為「可疑」並寫上原因，使用者可以改。

- VLAN 不一致：同一條 run 兩端 access VLAN 不同；一端是 trunk、另一端是 access；access VLAN 不在對端 trunk 的 tagged 清單內。
- PoE 不足：AP、IP Cam、IP Phone 接在沒開 PoE 的 Switch 埠。
- 速率或線材：銅線超過 100 m；光纖接到 RJ45 埠，或 RJ45 線接到 SFP 埠；兩端速率標示不同。
- LACP：同一個群組的成員接到不同的對端設備，或對端沒有設群組。
- 未接線或斷頭：路線在配線架或資訊座中斷，例如資訊座牆內埠沒有接到配線架。
- IP 設定：同網段重複 IP；終端 Gateway 和上游路由或防火牆的 IP 不符（有填才檢查）。
- 健檢結果也要有一個不用選起點的總覽，放在「顯示圖層」旁新增的「健檢」popover，列出整張圖的問題並可點選對焦。

## 四、影響範圍

- 任何線、埠或設備標成「故障」時，即時計算影響範圍：從網路入口出發做 BFS（沿用 `runGraph()`），排除故障元素後到不了的設備就是受影響設備。
- 受影響設備在畫布上加紅色斜線底紋，面板顯示「影響 N 台設備：…」清單。
- 也提供「模擬故障」：在任一設備或線上按「如果這裡壞了」，只計算影響範圍，不寫入紀錄，方便評估單點故障。

## 五、故障紀錄

- 「線路表」新增第三個分頁「故障紀錄」，欄位有：開單時間、起點、狀態摘要、故障點、處理備註、結案時間。
- 面板底部有「結案」按鈕：填寫處理方式（例如「更換跳線 P-01」），之後紀錄就變成唯讀。
- 支援匯出 CSV，內容也包含在專案 JSON 裡。

## 六、行動裝置與分享

- 現場人員常用手機。查線面板在 900 px 以下改成底部抽屜，沿用現有的響應式規則。
- 分享連結（`#p=…`）帶上 `&fault=<id>`，對方打開就直接進入該筆查線清單。唯讀模式下只能看，不能改狀態。
